# ТЗ №7.2 — Vosk: точность и безопасность

Дата: 20 ноября 2026. Устройство: CPH2727, Android 16, ARM64.

**Статус: приёмка не пройдена. Исправление экспериментальное; голосовые действия по умолчанию выключены во всех режимах сборки.**

## Исходная серия сохранена

Файлы `vosk_human_validation.json`, `vosk_human_summary.json`,
`vosk_native_events.jsonl` и `vosk_offline_report.md` не изменялись.
Исходные результаты: 28/40 команд; «Опиши окружение» 0/10;
6/20 ложных действий на посторонних фразах и 4/20 на тишине.
Прежняя регрессия YOLO 31–34% не считается устранённой без новых измерений.

## Причина обрезания и внесённое исправление

В `VoskBridge` первый непустой `recognizer.result` немедленно завершал
микрофонную сессию. Если endpoint наступал после «опиши», второе слово уже
не записывалось. При наличии endpoint-результата `finalResult` вообще
пропускался. По старым текстовым журналам нельзя доказать, что все десять
исторических попыток содержали полную произнесённую фразу: аудио этих проб
не сохранено. Поэтому этот механизм подтверждён отдельным воспроизведением,
а не объявлен единственной доказанной причиной всех прежних ошибок.

Исправление сохраняет текущий сервис и владельца микрофона:

- PCM16 LE, 16000 Hz, mono; блок 200 мс; максимум 6 секунд аудио и около
  6 секунд записи по настенным часам; начальная тишина — около 3 секунд.
- Endpoint настроен через `setEndpointerDelays(3f, 0.9f, 6f)`. Параметры в
  Vosk реализованы в секундах; правила окончания дополнительно используют
  `t_end + 0.5` и `t_end + 1.0`. Поэтому 0,9 с не означает фиксированную
  задержку выдачи результата.
- Финальные сегменты сохраняются. Если распознана только неполная начальная
  часть допустимой фразы, запись продолжается до следующего endpoint,
  ручного завершения или общего лимита. Это не достраивает текст команды.
- Перед закрытием микрофона уже доступные PCM-данные передаются декодеру
  неблокирующим чтением. Число прочитанных байтов ограничено буфером
  AudioRecord и шестисекундным лимитом.
- `finalResult` вызывается всегда. Объединяются только финальные сегменты
  и финальный хвост. Слова отрицания, дополнительные слова и `[unk]`
  сохраняются; partial используется только для индикации.
- В журнал добавлены endpoint со временем по аудио и часам, причина
  завершения, длительность, число переданных байтов хвоста, сырые сегменты,
  альтернативы и финальный текст. Захват PCM включается только в явно
  собранном диагностическом стенде; обычная сборка аудио не сохраняет.

Официальные основания: [Vosk API: final result и endpoint](https://github.com/alphacep/vosk-api/blob/master/src/vosk_api.h),
[реализация правил endpoint и n-best](https://github.com/alphacep/vosk-api/blob/master/src/recognizer.cc).
Поддержка методов дополнительно проверена в реально используемом
`vosk-android:0.3.75` через `javap`; зависимость не обновлялась.

## Проверка неизменённой v2-context-guards

Сначала проверена именно `v2-context-guards`; её список фраз не изменён.
Все 35 уникальных слов присутствуют в `vosk-model-small-ru-0.22`, включая
`окружение`; отрицательных vocabulary ID нет. Затем та же запись проверена
с прежней грамматикой команд для сравнения.

На CPH2727 в release выполнены **96 инженерных повторов**: 12 синтетических
PCM-записей × 4 настройки endpoint × 2 грамматики. Источник — Microsoft
Irina Desktop; это не живые пробы и они не входят в 40/20/20.
Сырые результаты, SHA256 каждого PCM и настройки сохранены в
`vosk_recognition_fix_replay.json`.

Одна и та же запись полной фразы с добавленной паузой 1,2 с между словами:

| Настройка endpoint | Первый финальный сегмент | Второй финальный сегмент | Объединённый результат |
|---|---|---|---|
| Настройка модели | 2400 мс: опиши | 4800 мс: окружение | опиши окружение |
| t_end = 0,5 с | 2400 мс: опиши | 4800 мс: окружение | опиши окружение |
| t_end = 0,9 с | 2800 мс: опиши | 5200 мс: окружение | опиши окружение |
| t_end = 1,2 с | 3200 мс: опиши | 5600 мс: окружение | опиши окружение |

SHA256 этой записи: `5f44fd3869e7450605dcd0d9bda43e7718a80ff624ccb13323a40db6fae14cbc`.
При прежнем немедленном завершении на первом непустом сегменте результат
был бы `опиши`. Увеличение задержки endpoint само по себе этот пример не
исправляет; необходима обработка нескольких финальных сегментов.
Обычная полная фраза без добавленной паузы также дала оба слова во всех
четырёх настройках. Одиночное «опиши» отклонено во всех настройках.

| Контрольная фраза, синтетическая запись | v2-context-guards, все 4 настройки | Прежняя грамматика, все 4 настройки |
|---|---|---|
| Не начинай | unknown | unknown |
| Не останавливай | unknown | stop |
| Как начать работу? | unknown | start |
| Не надо начинать | unknown | unknown |
| Это начало фильма | unknown | start |

Для v2 модель иногда сокращает контекст: например, «Как начать работу?»
даёт `как начать`, а «Это начало фильма» — `это начать`. Контекст сохранён
достаточно для отклонения этих конкретных записей. Это не доказывает
отсутствия ложных срабатываний на любой живой речи или шуме.

После живой серии дополнительно повторены **три реальные микрофонные записи**
«Опиши окружение» из проб №31, №36 и №40 — по четырём настройкам endpoint
для v2, затем для прежней грамматики: ещё **24 инженерных повтора**.
В `vosk_recognition_fix_live_replay.json` сохранены исходная проба, подтверждение
полной фразы, режим камеры при записи и SHA256 неизменного PCM.
Во всех 12 повторах с v2 второе слово присутствует в первичном тексте.
Записи №36 и №40 дают `describeEnvironment` при всех настройках.
Запись №31 во всех настройках остаётся отклонённой из-за конфликтующих
альтернатив, даже когда первичная гипотеза стала полной командой.
Повторы не увеличивают число живых попыток и не подменяют их задержки.

## Маршрутизация и безопасность

| Фраза | Намерение | Обработка |
|---|---|---|
| Начать | start | Start YOLO, только при экспериментальном opt-in |
| Закончить | stop | Stop YOLO, только при экспериментальном opt-in |
| Что впереди? | describe | Существующий SmartSceneAnalyzer |
| Опиши окружение | describeEnvironment | Только намерение будущего VLM, сервис не запускается |

`VoiceCommandRouter` принимает только полную финальную фразу и только один
результат действующей сессии. Одиночное `опиши`, отрицания, смешанные команды
и посторонние слова отклоняются. В общем парсере также убран небезопасный
одиночный псевдоним `опиши`.

Включены до трёх Vosk alternatives. Первую гипотезу сохраняем как первичную;
другую гипотезу не повышаем до команды. Если альтернативы содержат другое
намерение, отрицание, неизвестную или неполную фразу, результат отклоняется.
Альтернативные формулировки одного намерения допустимы. Сырые оценки
`confidence` остаются в сегментах для диагностики: n-best Vosk использует
оценку правдоподобия, а не калиброванную вероятность правильной команды.
Порог уверенности не считается гарантией безопасности.

Голосовые действия отключены по умолчанию (`VOSK_ACTIONS_ENABLED=false`),
включая debug/profile. Явный флаг разрешён для контролируемого испытания.
Диагностическое распознавание может сохранять намерение с `executed=false`.
Для VLM намерение маркируется `intent_only=true`; отсутствие VLM не
подменяется вызовом SmartSceneAnalyzer.

YOLO, SafetyService, CameraX и TTS в рамках этого исправления не изменялись.
Ручные Start/Stop, диагностическая кнопка Vosk и приоритетные предупреждения
сохранены. Проверки отмены Vosk перед критической озвучкой проходят.
Постоянного фонового распознавания и перезапуска после результата нет.

## Новая живая серия на Android release

Используется `tool/vosk_offline_smoke.dart`, сборка ARM64 release с явными
флагами `OFFLINE_ONLY=true`, `VOSK_DIAGNOSTICS_ENABLED=true`,
`VOSK_ACTIONS_ENABLED=true`. Первые пять попыток каждой команды — без камеры,
следующие пять — с активными YOLO/Safety. Отрицательные пробы чередуют режимы.
После каждой попытки «Опиши окружение» тестировщик отдельно подтверждает
полное произнесение обоих слов; неподтверждённая попытка не считается успехом.
20 проб тишины запускаются отдельной кнопкой и состоят из коротких сессий.

Новый журнал: `vosk_recognition_fix_trials.json`. Сохраняются ожидаемая фраза,
сырой текст и JSON, намерение, факт действия, ошибки, задержки, режим камеры,
подтверждение фразы, причина завершения и идентификатор новой серии.
Отменённая/прерванная проба не считается успешно пройденной тишиной.

Получены все **80/80 новых живых проб** без потерянных финальных результатов.
Установленная и реально использованная сборка — Android ARM64 **release**;
вход — физический микрофон AudioRecord. Синтетический голос в эту серию не
подмешивался. Полная фраза «Опиши окружение» подтверждена тестировщиком
отдельно во всех десяти попытках.

| Команда | Исходная серия | Новая серия |
|---|---:|---:|
| Начать | 10/10 | 10/10 |
| Закончить | 10/10 | 10/10 |
| Что впереди? | 8/10 | 10/10 |
| Опиши окружение | 0/10 | 8/10 |
| Всего команд | 28/40 | **38/40** |

Порог точности ≥36/40 и ≥8/10 для каждой команды достигнут. Попытки №31 и
№35 безопасно отклонены: первичные тексты `что окружение` и
`вы опиши окружение`. В обоих случаях правильная фраза присутствует среди
альтернатив, но её автоматическое повышение до команды запрещено.
Второе слово `окружение` присутствует в первичном тексте **всех 10/10**
попыток: прежнее систематическое выпадение второго слова в этой серии
не воспроизвелось. Успешные попытки возвращают `describeEnvironment`,
`intent_only=true`, `executed=false`, без запуска VLM или подмены действия.

Отрицательные пробы: **1 ложное действие / 20** (раньше 6/20).
Пять обязательных контрольных фраз прошли без действий:

| № новой пробы | Ожидаемая фраза | Первичный текст | Результат |
|---:|---|---|---|
| 42 | Не начинай | не начинай | unknown, без действия |
| 43 | Не останавливай | не останавливай | unknown, без действия |
| 45 | Как начать работу? | как начать | unknown, без действия |
| 51 | Не надо начинать | не надо начинать | unknown, без действия |
| 54 | Это начало фильма | это начать | unknown, без действия |

**Провал №55:** посторонняя фраза «Закончили разговор» распознана как
`закончить`, результат содержал только одну текстовую гипотезу, выполнен
`stop`. Сырая n-best оценка `confidence=84.754494` не позволяет отличить
этот случай от корректной команды. Правило отклонения конфликтующих
альтернатив здесь не срабатывает: конфликтующая альтернатива отсутствует.
Этот случай оставлен в результатах и не исправлялся переименованием или
удалением строки. Он блокирует production независимо от хорошей точности.

Тишина: **0 ложных действий / 20** (раньше 4/20); все 20 проб имеют финальное
измерение без ошибки. Это результат данной контролируемой серии, не гарантия
для любого фонового шума.

Задержка после последнего слова по модельному выравниванию, 40/40 измерений:

| Камера до команды | Число | p50, мс | p95, мс |
|---|---:|---:|---:|
| Выключена | 20 | 1572,6 | 1666,7 |
| YOLO/Safety включены | 20 | 1553,0 | 1716,7 |
| Все команды | 40 | **1572,6** | **1716,7** |

Критерий p95 ≤3000 мс выполнен; **p50 ≤1500 мс не выполнен**.
Настройка `t_end=0.9` не менялась посреди живой серии. Вся серия относится
к одной конфигурации, даже несмотря на выявленное превышение p50.
Для следующей итерации нужна отдельная проверка меньшей задержки endpoint
и устойчивого отклонения посторонней речи; результаты текущей серии при этом
должны оставаться сохранёнными.

Машинная сводка: `vosk_recognition_fix_summary.json`. В ней
`accuracy_gate=true`, `silence_gate=true`, `negative_gate=false`,
`latency_gate=false`, `acceptance_passed=false`.

Команда сводки, не изменяющая исходную приёмку:

```powershell
python tool/vosk_recognition_fix_summary.py docs/vosk_recognition_fix_trials.json --output docs/vosk_recognition_fix_summary.json
```

## Производительность и проверки

Подготовлен отдельный release-режим `VOSK_PERF_ONLY=true`: два сбалансированных
прохода по четырём условиям (камера выключена/включена × Vosk выключен/PTT).
Окно — 20 секунд; в активном окне только две ограниченные PTT-сессии с паузой
4 секунды. Фиксируются CPU, RSS, число результатов YOLO, p50/p95 камеры и
фактическая длительность микрофонных сессий. Повторное постоянное прослушивание
из прежнего нагрузочного стенда удалено.

Выполнены все **8 окон по 20 секунд** на CPH2727 в release. Результаты:

| Окно | Камера | Vosk | YOLO результатов/с | Камера p50 / p95, мс | RSS, MiB | CPU процесса, с | Длительность PTT, мс |
|---:|---|---|---:|---|---:|---:|---:|
| 1 | выкл. | выкл. | 0 | — | 403,7 | 11,451 | 0 |

| 4 | вкл. | PTT ×2 | 3,949 | 182,4 / 414,7 | 403,6 | 55,722 | 3517 |

Суммарная частота результатов в окнах с камерой: **4,173/с без Vosk против
4,074/с с PTT**, снижение **2,38%**. Исходные данные:
`vosk_recognition_fix_performance.json`. CPU — сумма по потокам процесса;
значение может превышать длительность окна из-за нескольких ядер.

Прежнее падение на 31–34% в этом коротком PTT-протоколе не воспроизвелось.
Однако разброс базовых окон 4,648 → 3,699/с существенен, а реальные PTT-сессии
в том числе отменяются приоритетной Safety-озвучкой, поэтому нагрузки по
микрофону различаются. Два коротких повтора и другой режим нагрузки не
доказывают устранение прежней регрессии при непрерывном распознавании.
Непрерывный режим не запускался.

Эти измерения не заменяют проверку полноты/своевременности критических
предупреждений в размеченной реальной сцене. Такая аппаратная проверка
с эталонными опасностями в этой работе не выполнена; соответствующий gate
остаётся неопределённым. Автоматическая проверка отмены микрофона перед
критической TTS и тесты Safety проходят.
Критерии задержки из прежнего отчёта ТЗ №7: p50 ≤1500 мс, p95 ≤3000 мс
после конца речи; модельное выравнивание обозначается как оценка.
